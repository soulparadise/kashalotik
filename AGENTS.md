# Kashalotik — рабочий регламент

Этот файл является главным постоянным контекстом проекта для Codex. Перед любыми изменениями прочитать его и связанные документы в `docs/`.

## Цель проекта

Создать полноценный современный сайт детского бассейна «Кашалотик» на основе утверждённого пользователем визуального концепта и актуальной информации с `https://kashalotik.ru/`.

## Неприкосновенные основы дизайна

- Основной визуальный референс: `public/assets/images/reference-hero.png`.
- Использовать оригинальный актуальный логотип: `public/assets/images/logo-2026.svg`.
- Крупные декоративные заголовки набираются Borsok.
- Основной текст, меню, кнопки и карточки набираются Nunito.
- Основная палитра: тёмно-синий, голубой, розовый и очень светлый голубой фон.
- Сохранять дружелюбный детский характер: мягкие формы, волнистые переходы, пузырьки, водяные брызги и ненавязчивые анимации.
- Не возвращать декоративные пузыри по левому и правому краю всей страницы.
- Не заменять оригинальный логотип и не перерисовывать его без прямого указания пользователя.
- Не менять визуальную основу главной страницы радикально без согласования.

## Структура и контент

- Все страницы используют общий `Header.astro` и `Footer.astro`.
- Внутренние страницы используют общий `PageHero.astro`.
- Верхнее меню должно выглядеть одинаково на всех страницах.
- Пункты меню: «О бассейне», «Занятия», «Расписание», «Команда», «Водоподготовка», «Правила», «Контакты».
- Отдельной страницы и пункта меню «Отзывы» нет.
- Порядок ключевых блоков главной: занятия → абонементы и цены → тренеры → почему выбирают нас → остальные блоки.
- Актуальные бизнес-данные при необходимости сверять с `https://kashalotik.ru/`, но не менять существующие данные без причины.

## Поведение и анимации

- Анимации должны помогать восприятию, а не мешать чтению.
- Уважать `prefers-reduced-motion`.
- Карточки тарифов не должны менять высоту при наведении.
- На внутренних страницах кит находится внутри контейнера контента, смотрит влево и показывает случайную фразу при наведении или фокусе.
- Стрелки главного слайдера закреплены по краям центрального контейнера, а не окна браузера.

## Работа с изображениями

- Не перезаписывать исходники без прямого указания: создавать версии с понятными суффиксами.
- Улучшенные изображения второго и третьего слайда: `pool-action-2-enhanced.png` и `pool-action-1-enhanced.png`.
- Декор второго и третьего слайда: `slider-splash-blue.svg` и `slider-splash-pink.svg`, дополненный пузырьками через CSS.
- На втором и третьем слайдах кит не нужен.

## Технологии

- Astro, TypeScript, Swiper и Motion.
- Сайт собирается статически.
- Основная команда разработки: `pnpm dev`.
- Проверка и сборка: `pnpm build`.
- GitHub Pages публикуется workflow `.github/workflows/pages.yml` только из ветки `main`.

## Git и публикация

- Локальные изменения и локальные коммиты разрешены.
- Никогда не выполнять `git push`, не публиковать на GitHub и не запускать внешний деплой без прямой просьбы пользователя в текущем разговоре.
- При запросе на деплой сначала убедиться, что изменения зафиксированы, затем отправить `main` и проверить GitHub Actions и опубликованные файлы.
- Не отправлять рабочую ветку ради деплоя: это ранее создавало конфликт параллельных запусков Pages.
- Сохранять пользовательские и несвязанные изменения в рабочем дереве.

## Стиль совместной работы

- Пользователь предпочитает быстро видеть результат: менять и показывать.
- Не выполнять расширенные проверки, если пользователь прямо просит только внести визуальное изменение и показать его.
- Перед существенным визуальным изменением кратко сказать, что именно будет изменено.
- Для локального показа давать кликабельную ссылку на предпросмотр.
